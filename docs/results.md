# Scan results

## Summary

These numbers were measured with `task ci`, on the SonarQube Community version pinned in `compose.yaml`, with the default "Sonar way" quality profile.

`task assert` fails when a rule listed here stops firing, so this page and the minimums in `Taskfile.yml` are always updated together.

Coverage is partial on purpose: the tests exercise some branches of the showcase code and leave others out.

## Surprises

- Go has neither `S2068` nor `S4790`, so the password and MD5 code that raise issues in other languages raise nothing.
  A clean dashboard can therefore mean that a rule is missing.
- `go:S1192` fires on the HTTP header strings in `main.go`, and not on the repeated return values of the showcase.
- `java:S2486` and `java:S108` do not fire on an empty catch block when it contains a comment.
- Any comment containing `TODO` raises `S1135` on its own.
- Rules that need to prove a problem at runtime, such as division by zero (`S3518`), stay silent on code this small, so the samples do not rely on them.
